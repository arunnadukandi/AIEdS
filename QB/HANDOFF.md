## 1. The task, in one paragraph

The project folder (mounted root, referred to below as `PROJECT_ROOT`) contains subfolders `term 1` through `term 7`. Each term folder has a `books according to syllabus` subfolder (exact spelling varies — term 1 uses "books acoording to syllabus", a typo, not a mistake to fix) containing textbook PDFs. There is also a reference CSV at `PROJECT_ROOT/8051_Microcontroller_Question_Bank.csv` — a hand-made 1000-row MCQ bank that defines the target schema and difficulty-distribution pattern. The job: generate a 1000-question multiple-choice CSV **per syllabus PDF**, with difficulty graded from 0.05 to 1.00, matching the reference bank's structure, and save each into a mirrored `QB/term N/<book-name>.csv` folder tree. Only PDFs inside "books according to syllabus" folders are in scope — NOT "books not according to syllabus" and NOT "reference material" subfolders.

## 2. Output location and path mapping

- **Final deliverables** go to: `PROJECT_ROOT/QB/term N/<book filename base>.csv` (one CSV per book, folder per term, mirroring the term structure).
- **Working/scratch generator scripts** live in the temp outputs sandbox, one folder per book: `outputs/qb_<shortname>/` (e.g. `qb_razavi`, `qb_sedra`, `qb_sudhakar`, `qb_nas`). Each such folder contains `base_utils.py` (shared helper library, see §4) and `gen.py` (the book-specific question generator that imports/execs base_utils and writes the CSV).
- If you are a fresh agent in a NEW session, your sandbox paths will differ from the ones referenced in old commands below — re-resolve `PROJECT_ROOT` and the outputs sandbox path at the start of your session (list your mounted folders / check your system prompt for the mapping). The important thing is the **folder structure and naming convention**, not the literal absolute paths quoted here.

## 3. CSV schema (must match exactly)

```
Sl No, Question, Option 1, Option 2, Option 3, Option 4, Correct Option, Level of Difficulty, Chapter
```

- `Sl No`: sequential 1–1000.
- `Correct Option`: integer 1–4, the **position** of the correct answer after shuffling (not always the same column).
- `Level of Difficulty`: one of 20 values, 0.05, 0.10, 0.15, ... 1.00 (step 0.05), formatted **without trailing zeros** — e.g. `0.1` not `0.10`, `1.0` not `1.00`. Exactly 50 questions per level (20 × 50 = 1000).
- `Chapter`: **added per explicit user request**, not present in the original reference CSV. Must cite the real chapter (and page number where feasible/relevant) the question content was drawn from, e.g. `"Ch 3 – Fourier Series (p. 57)"`. This column must be non-empty on every row.
- The original reference CSV (8051 one) does NOT have a Chapter column — that's fine, it predates the requirement. Every book generated by you must have it.

## 4. Reusable code infrastructure (READ THIS BEFORE WRITING A NEW GENERATOR)

Every book so far has followed the same two-file pattern: copy `base_utils.py` from the most recently completed book's folder into a new `qb_<newbook>/` folder, then write a book-specific `gen.py` that imports it (or is concatenated with it — check the existing gen.py files for the exact wiring pattern) and defines the 20 difficulty levels.

`base_utils.py` provides:

- `mutate_value(v)` — type-aware distractor mutator for genuine Python objects (bool/int/float/str/list/tuple/dict/set). Produces plausible wrong values of the same shape/type. **Never** falls back to placeholder junk like `opt_0`/`error_N` — this was the exact bug the user complained about in the pilot and it must never reappear.
- `build_distractors(correct_val, seed_variants=None, n=3)` — wraps `mutate_value`, dedups via `repr()`, deepens search by mutating the mutations if needed. Use this for genuine typed Python values (e.g. definitional/term-matching questions).
- `numeric_distractors(value_str, n=3)` — **use this instead of `build_distractors` for any pre-formatted numeric-with-units display string** (e.g. `"25 kΩ"`, `"78.53%"`). Regex-splits magnitude from unit suffix, perturbs the number multiplicatively (×2, ×0.5, ×10, ×0.1, ×3, ÷3, ×-1, ×1.5, ×0.75), re-attaches the unit, preserving formatting style. `build_distractors` on formatted numeric strings produces garbled quote-wrapped nonsense (a real bug hit early on) — don't use it for this case.
- `add(level_list, q, correct, distractors, diff, chapter)` — shuffles `[correct] + distractors` into 4 options, records the correct 1–4 position, appends the row tuple.
- Phrasing-variant pools: `PHR_DEF`, `PHR_METHOD`, `PHR_REVERSE`, `PHR_EVAL`, `PHR_FACT` — each a list of 4–5 alternate question templates. **Critical recurring bug**: if a fact/term pool has fewer than 10 unique items and you need 50 questions from it, cycling through only 5 phrasings will eventually produce **exact duplicate rows**. Rule of thumb: any definitional term-dict feeding a `while len(L) < 50` loop must have **at least 10–11 entries**, ideally more. Always check pool size before wiring up a level.

Generator pattern used in every level block (see any `gen.py` for full examples, e.g. `qb_sudhakar/gen.py` or `qb_nas/gen.py`):

```python
L = []
items = list(some_term_dict.items())   # or a `cases` list of (question, correct, chapter) tuples
i = 0
while len(L) < 50:
    term, desc = items[i % len(items)]
    cycle = i // len(items)
    others = [d for t, d in items if d != desc]
    distractors = random.sample(others, 3)
    q = PHR_DEF[cycle % len(PHR_DEF)].format(x=term)
    add(L, q, desc, distractors, 0.05, ch(1))   # ch() = book-specific chapter/page formatter
    i += 1
level_data[0.05] = L
```

For numeric/calculation levels, a `cases` list of `(question_text, correct_value_str, chapter_str)` tuples is pre-computed (with the correct answer **calculated programmatically from real formulas**, never hand-guessed), then the same `while len(L) < 50` cycling pattern applies using `numeric_distractors(correct)` instead of `random.sample`.

Each book defines its own `CHAP` dict + `ch(chapter_num, sub=None)` helper to format the Chapter column correctly for that book's own page-numbering convention (see §6 — this varies per book and requires inspecting the actual PDF).

## 5. Mandatory validation after every book (do not skip)

After generating a book's CSV, verify programmatically:

1. Exactly 1000 data rows (1001 lines with header — note: if any question contains an embedded real newline inside a quoted CSV field, e.g. multi-line code snippets, `wc -l` will report MORE than 1001 lines even though there are exactly 1000 logical rows. Use `csv.reader` / `pandas.read_csv` row count, not `wc -l`, to check row count).
2. `Sl No` sequential 1–1000.
3. Difficulty distribution exactly 20 levels × 50 rows each (0.05...1.00 step 0.05).
4. No empty fields anywhere.
5. `Correct Option` ∈ {1,2,3,4}.
6. Zero duplicate `Question` texts (exact string match).
7. Zero rows where the 4 options are not all distinct.
8. Zero "junk placeholder" distractors — regex-check for patterns like `opt_\d`, `error_\d`, `x_\d` etc. Must be zero matches.
9. Zero quote-wrapped/garbled numeric distractors (a sign `build_distractors` was wrongly used instead of `numeric_distractors`).
10. `Chapter` column fully populated, and spot-check a handful of entries against the actual PDF to confirm they're plausible.

Fix and re-run before considering a book done. This checklist has caught real bugs in every single book so far — do not shortcut it.

## 6. Chapter/page citation sourcing strategy

Depends on what each PDF's own table of contents provides. Determine per-book:

- **Extract text**: `pdftotext -layout "<pdf path>" out.txt` — **always redirect output** (`> /tmp/x.log 2>&1`) when combined with grep/wc in the same shell call; large/scanned PDFs can trigger a tool token-limit error otherwise.
- **If the book has real printed page numbers in its TOC** (e.g. Sedra/Smith, Sudhakar): use those numbers directly, e.g. `ch(3, 57)` → "Ch 3 (p. 57)".
- **If the book uses chapter-relative page numbering** (e.g. Ravish Singh, format like "3.12"): format accordingly, e.g. `ch(3, 12)` → "Ch 3 (p. 3.12)".
- **If only running headers are available with no usable page numbers** (e.g. Razavi, Oppenheim): count form-feed characters (`\x0c`) in the extracted text to map text position → physical PDF page number. `pdfinfo <pdf>` gives total page count as a sanity check (should equal the count of `\x0c` in the extracted text).
- For scanned/OCR'd PDFs with poor text quality (Sedra, Oppenheim have OCR garbling in places), it's acceptable and expected to rely on your own domain knowledge of these extremely standard, canonical textbooks for content accuracy — use the extracted text mainly to confirm chapter structure and page boundaries, not for literal quoting.

## 7. Known infrastructure bugs and their fixes (avoid repeating these)

- **Null bytes after `Write` tool**: creating a new `.py` file via the `Write` tool sometimes appends trailing `\x00` bytes, breaking `import`/`ast.parse` with "source code string cannot contain null bytes". Fix immediately after every such `Write` call: read the file in binary, strip `\x00`, write back.
- **Bash heredoc backslash escaping**: `cat >> file << 'PYEOF'` (quoted delimiter) does no shell interpretation — literal `\n` in the heredoc becomes literal 2-char text in the file. If you need Python source that, when later executed, produces a REAL newline (e.g. multi-line code inside an `exec()`-able string), you need a single backslash `\n` in the heredoc. If you want the file's Python source to itself contain the literal 2-character escape sequence `\n` as visible text (e.g. a question about what the `\n` escape code means), you need a double backslash `\\n` in the heredoc. Getting this backwards has caused real bugs (mid-question newline injection, `SyntaxError: unexpected character after line continuation`). Think through which one you want before typing it.
- **`pdftotext`/`grep`/`wc` combined in one bash call on large PDFs**: can exceed the tool's output token limit even though the actual answer needed is small. Always redirect to a log file and only `cat`/`grep` small summaries out of it.
- **Distractor generator choice**: `build_distractors()` for real typed Python values; `numeric_distractors()` for pre-formatted numeric+unit display strings. Using the wrong one produces garbled or placeholder-junk distractors — this was the user's original, explicit complaint on the pilot book. Never regress on this.
- **Small term pools cycling into duplicates**: any dict/list of facts feeding a 50-question level via modulo-cycling must have ≥10–11 entries or you will get exact duplicate question+answer rows once the phrasing pool (5 variants) has been exhausted more than once.
